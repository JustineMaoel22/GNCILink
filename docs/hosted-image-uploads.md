# Admin image uploads

Saved images are limited to 5 MB (5,242,880 bytes). Larger originals are sent to
the existing photo optimizer before staging or publishing. The server optimizes
oversized originals again when needed, and checks the resulting file size.
Images already within the limit retain their original bytes. If optimization is
unavailable or fails, the image is rejected and the existing modal explains the
5 MB limit. Automatic optimization requires the PHP Imagick extension.

Program and homepage banners and program pictures use `imageUploadMime()`:
Fileinfo when available, or server-side raster image detection when unavailable.
File size, allowed formats, authentication, permissions and CSRF checks still apply.
PDF and video uploads continue to require Fileinfo.

The previous generic "larger than the server allows" message is generated by
PHP's upload error, not by the application's 5 MB check. A host with a 2 MB PHP
limit rejects a 3 MB image before the application receives its bytes. A combined
multipart request can also exceed `post_max_size` even when every file is valid.
Program slideshow additions now send one image per request. Program requests
that PHP discards return a request-size error rather than a CSRF/session error.

Deploy these files together, retaining their relative paths:

- `assets/js/image-upload.js`
- `assets/js/content-edit.js`
- `includes/image-upload.php`
- `admin/admin-functions.php`
- `admin/action/program-page-handler.php`
- `admin/action/optimize-image.php`
- `.user.ini`
- `.htaccess` (merge the `.user.ini` access restriction with any host-added PHP handler directives)

Upload the repository `.user.ini` to the website root for PHP-FPM/shared hosting.
Its limits match the existing Docker `uploads.ini` and preserve video uploads.
Upload `.htaccess` as well to block HTTP access to `.user.ini`.
PHP-FPM may cache `.user.ini` settings for several minutes. Some providers lock
these settings; in that case the provider must enable the larger PHP limits.
The authenticated endpoint
`/admin/action/page-content-handler.php?action=upload_environment` reports the
effective PHP upload and request limits without exposing credentials.

Upload directories must be writable by the website's PHP user. Database writes
use the existing media-library and program-item tables. No schema migration is
required. Failed program-item saves roll back database writes and remove newly
stored files/media; existing published images are retained.
