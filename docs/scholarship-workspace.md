# Scholarship categories and details

The public `/scholarship` route uses the Tuition and Fees layout, sidebar, document header and native embedded PDF viewer styles. Categories expand into opportunities; search matches category and scholarship names. Selection is reflected in the URL, with Back/Forward support and server-rendered category/opportunity links. Mobile navigation is collapsible. The content panel shows only the selected PDF with Download/Open PDF controls, or a document-coming-soon state when no PDF is attached. Introductions, photos, award cards and separate scholarship detail sections are not rendered.

Content Editor → Scholarship Opportunities → Manage scholarships opens a responsive modal dialog. Search filters categories and scholarship titles; expandable category cards display scholarship counts, readable titles and PDF status. Category and scholarship three-dot menus contain secondary actions, including accessible Move up / Move down controls. Drag handles support mouse and touch reordering: categories move independently, and scholarships move only within their category. Clear search before dragging. Adding or editing uses labeled forms inside the dialog, with validation, confirmation before deletion and success feedback.

A category must be empty before deletion; the confirmation view explains how many scholarships it contains and blocks deletion until they are moved or removed. Opportunities can be moved to another category through Edit title or category. Keep at least one category. Existing descriptions and optional fields remain stored but are not shown in the PDF view or metadata form.

Scholarship photo definitions, upload handling, editor controls and the old requirements-dialog fallback have been removed. Restored older drafts discard photo edits, and obsolete photo payloads cannot recreate database photo references. Requirements and other scholarship details should be included in the uploaded PDF. Legacy requirement records and physical image files remain stored. The CLI-only `scripts/cleanup-scholarship-photos.php` previews retired `scholarship_image_` records; `--apply --archive /private/path/photos.json` deletes only those references on local Docker after saving a private rollback archive and verifying restoration in a temporary table. All other tuition/scholarship content is compared before commit and preserved. `--restore --archive /private/path/photos.json` restores absent archived records in the same database. The verified local database had no scholarship photo references to delete. No schema migration is required.

The dedicated `scholarship_categories` table stores category IDs, names and display order after the category migration. `category_id` preserves the existing slug IDs used by entry assignments and public URLs; `category_name` stores the editable label. The existing `tuition_fee_content` table continues to store the `scholarship_entries` JSON record and PDF references. A synchronized `scholarship_categories` JSON record is retained there only for compatibility and rollback. Entries support `description`, `eligibility`, `benefits`, `application`, `information`, optional `url` and optional `pdf`. Array order determines public display order. Run the category migration described below to activate the dedicated table; until then, the legacy category reader remains available.

For PDF uploads, select a scholarship and use the visible Upload PDF / Replace PDF button above its viewer, or choose Upload PDF / Replace PDF from its three-dot menu in Manage scholarships. The add/edit form also provides a PDF input. File selection stages a preview; Done closes management and Publish saves through the existing confirmation/approval flow. The dialog traps keyboard focus, supports Escape, restores focus on close and scrolls within the available viewport height.

Until the first catalog publication, existing Basic Education, College and Athletic opportunities are included through stable legacy references, alongside previously saved PDF opportunities. Original text, award percentages, requirements and image fields are retained in storage. `scholarship_catalog_version` marks an explicitly saved catalog so a removed legacy opportunity does not reappear. Deleting an opportunity retains stored files and legacy fields. Back up these three catalog records and the existing scholarship content before reverting to an older implementation that only understands the two original categories.

The existing authenticated scholarship handler saves content, categories, opportunities and uploaded file references in one transaction. Existing role permissions, CSRF, publication confirmation, review routing and editor version checks remain in the shared request boundary. New PDF paths must come from validated uploads; retained references are checked against saved entries. Failed saves roll back content and remove newly uploaded files.

- Run the same command with `unauthorized` or `csrf` for rejected-write checks.
- `node tests/scholarship-workspace-browser-test.cjs` — local public/editor navigation, category controls, optional details/PDF preview, undo/redo, draft restoration and responsive screenshots, without publishing content.


## Dedicated category migration

Deploy the updated component, handler, migration files and `database/scholarship-categories.sql` together. Back up the database first. Run `php database/migrate-scholarship-categories.php --apply --archive /private/backups/scholarship-categories-before.json` from the project root; the archive must be a new file outside the web root. On local Docker use `docker compose exec -T --user www-data web php database/migrate-scholarship-categories.php --apply`. No web request creates tables automatically.

The migration creates `scholarship_categories` and uses the existing additive `content_migrations` registry. It copies existing category JSON (or the existing editable defaults when nothing has been published), preserves IDs/names/order, validates existing assignments and only then activates `scholarship-categories-v1`. It shares the editor write lock, seeds transactionally and is idempotent. No entries, PDF files, photos or other tuition records are deleted. Subsequent category saves write rows and the compatibility mirror in the same transaction as entries and page text. The handler retains existing authorization, CSRF and approval routing.

To switch back, run `php database/migrate-scholarship-categories.php --rollback` before reverting the code. This copies current category rows to the compatibility mirror and disables the marker; it retains the dedicated table. Reapply only after confirming its retained rows still match the mirror. Do not import the CREATE TABLE SQL alone as a completed migration: the CLI also seeds and enables the reader.

Verification adds `docker compose exec -T --user www-data web php tests/scholarship-workspace-test.php normalized` for dedicated-table migration, saved-category preservation, CRUD/order, authoritative reads, transactional rollback and reversible activation. The legacy test and `unauthorized`/`csrf` variants remain supported. Tests shadow storage with connection-local temporary tables and never change application categories. The local migration created two categories and saved its pre-migration snapshot at `/tmp/gnci-scholarship-categories-before-20261110.json` inside the web container; copy snapshots to durable private backup storage before recreating a container.
